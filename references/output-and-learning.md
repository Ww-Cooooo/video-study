# 输出、反馈与学习记录

## 先让用户知道具体吸收了什么

优先回应用户关注点，再呈现全面覆盖中发现的其他价值。按实际内容组织，不强制每份报告填满同一种表格：

- **知识与做法**：学到什么，关键条件、步骤、例子和例外；哪些主张还未核实。
- **表达与结构**：原片的具体安排、位置、作用和限制，不只列技巧名称。
- **相关声画**：真正观察到的视觉信息、声音或动态；没取得就说明未覆盖，不用空白章节充数。
- **怎样用于当前任务**：具体使用位置和改动；涉及相关工具/资源时给可信入口、已查到的采用条件、推荐的具体用法和最小下一步。已交小样就指向产物，未运行就不称实测。
- **覆盖与缺口**：实际看的区间/信息层、缺失材料或尚未理解透之处，以及它们影响哪些结论。

重要发现保留可定位原例、解释、适用场景和采用办法。长证据按需展开，不把“报告短”实现为只给抽象结论，也不把“全面”实现为重复全片转写。作者研究补样本选择与共同点/例外，制作研究补过程与可行实现，知识研究保留主张和操作条件。

## 先自查，再邀请补充

交付前回看本次范围与内容骨架，检查：用户明确关注是否回应，后半段/结尾是否漏读，必要例子与限制是否被摘要抹掉，声画独有信息是否处理，相关工具/方法是否只提了名字却没调查用法，应用是否真发生。原片未说的事不能补成已学内容，外部补查单独注明来源。仍有与目标相关的使用缺口时，结尾指向它的最小下一步，不直接以“发下一条视频”跳过；用户暂停该分支时遵从当前安排。

用户可以直接指出“我想让你学的是这里”或“你漏了这个例子”。简短说明这个补充入口即可，不要求逐项验收、不机械索取评分，也不把“还有遗漏请指出”当成免于自查的理由。

## 补充后更新原结果

回到用户所指片段及原记录，确定漏在材料、理解、取舍还是应用。若兼有多个原因或还不确定，照实说明。处理时保留：用户实际指出什么、原来怎样判断、这次补了或改了什么、影响哪些结论/产物。简短纠正可以直接写回原条目，不必每次新建报告。

补取材料只补真实缺口；重读只扩大到必要前后文；取舍错误修正范围判断；应用遗漏修改实际稿件/方案。只有发现广泛受影响的共同问题，才扩大复查，不例行重做整片。用户改变学习目标与助手原先遗漏分开记录。

观察原例、建议采用、保存成功和效果有效不是同一件事。修订后还需用相关结果验证，不能靠“我解释了原因”声称解决。撤回的结论保留必要历史并标清，不与新结论同时作为当前建议。

## 保存与召回用原有入口

用户要求保存或任务已有落盘授权时，复用同一任务目录、报告和证据位置；未获授权时只在对话交付。报告可承载多项发现，不必每项建文件、建组件或晋升正式记忆。

入口用一句用途、自然说法和相对链接连接正文；保存后从用户会说的任务入口实际读到当前记录，核对有效、撤回和待反馈状态。单条索引失败只修该条，保留已写内容，不能让全部能力停用。

按需读取证据，不将完整研究或全部记忆常驻加载。新的来源、纠正与任务反馈写回相关条目；不重复存已经存在的同源结论，不靠无限追加规则掩盖矛盾。共享 Skill 不写私人目录、账号或个人偏好，公开分享与私有证据分开。

## 状态与验证

| 状态 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 观察到/已理解整理 | 有原例、位置和可核对解释 | 已获得作者全部风格或事实都已外部核实 |
| 建议试用 | 有具体用法与条件 | 已在实际作品采用 |
| 已实际采用 | 对应产物发生了可指出的改动 | 质量、观看或转化效果必然提升 |
| 效果有证据 | 用户反馈或真实使用结果支持特定结论 | 全部题材、平台与未来任务都有效 |

验证围绕本次改变：知识是否能解释或照条件应用，信息是否更清楚，例子是否保住，方法是否适配用户，实际声画是否支持结论；有可比条件时再比较耗时与结果。不要建立没有意义的总分、固定成功次数或每次都跑全套测试。

结果没有达到目标，就修正原理解或采用条件；没有反馈就保持待反馈。保存/召回只证明接通入口，不能作为成熟度提升的依据。正式学习资产仍遵守当前项目的独立证据和用户授权，不由本 Skill 自动晋升。
